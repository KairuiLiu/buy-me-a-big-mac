# 爱发电付款通知与感谢小票

爱发电和 Stripe 支付链接可同时配置, 至少填写一种即可生成分享链接. 支持者选餐后选择付款方式, 再在新标签页前往对应平台. 两个渠道的小票开关分别生效. Stripe 的配置与返回小票流程见 [Stripe 接入说明](stripe.md). 下文仅说明爱发电付款通知.

作者共用一个公开通知地址：`https://你的域名/api/payments/webhook`。无需注册接入、保存作者凭证或提交爱发电 API Token。支持者付款链接中的 `custom_order_id` 对应 D1 中的短期赞助关联（intent），通知到达后，原浏览器凭 `readToken` 查询并展示感谢小票。

这项功能只用于感谢小票，不发货、不发放权益，也不创建麦当劳订单或执行付款。小票显示“已收到付款通知”，不作为独立支付凭证。

## 页面使用流程

1. 作者填写爱发电 UID，开启“付款后送上一张感谢小票”。页面立即显示本站统一的公开 Webhook 地址，可直接复制到[爱发电开发者后台](https://afdian.com/dashboard/dev)并保存。同一账号的不同项目共用此地址，无需逐项目配置。
2. 在爱发电后台点击“发送测试”，以后台的成功提示为准。本站没有作者接入注册、配置恢复或连接测试按钮；固定测试样例只检查连通性，不归属某位作者，也不会产生付款状态。
3. 生成的分享链接以 `h=1` 表示开启通知，对应配置 `notifications: true`；关闭时使用 `h=0`。关闭开关只影响之后生成的链接，已分享链接的设置不会改变。未开启通知时，付款直接在新标签页打开爱发电，本站保留选餐页，不创建 intent。
4. 支持者选餐并在小票末尾留言后, 点击 "就这样" 进入付款方式选择页. 选择爱发电并确认时先预留新标签页, 再创建 intent, 并在当前浏览器保存小票与查询凭证. 关联创建失败或本地保存失败时会显示原因, 可重试或选择仅前往爱发电.
5. 付款链接带上 `custom_order_id=intentId`，在新标签页打开爱发电；原页面切换到 `/thanks/<intentId>`。支持者付款后切回该页查看通知。首次查询到 `notified` 时播放礼花，也可主动重播。`unknown` 只表示本站无法确认，应前往爱发电查看订单。

Webhook 是服务器请求，不会打开支持者浏览器或自动回跳。查询凭证不会进入感谢页 URL、分享链接或付款备注；换浏览器打开感谢页链接，无法凭链接恢复查询。

付款备注由 `src/lib/donation-remark.js` 生成：留言在顶部，下一行“赠予”的右侧为项目名或用户名，再按商品 / 数目 / 价格的 20 / 8 / 6 个显示位排成小票，包含各行小计、总件数与总金额，尾签为 `Create by Buy me a Big Mac`。对齐以等宽字体为准，爱发电控制实际显示字体。浏览器小票中的 `ReceiptItem.amountCents` 保存当次行小计，重新打开爱发电时沿用该快照；历史小票缺少行金额时显示 `—`，不猜测价格。

## 接口

三个接口均使用 JSON POST，响应不缓存。浏览器的创建和查询请求只允许本站来源，Webhook 接收爱发电服务器请求。以下尖括号内容需替换为实际值。

### 创建短期赞助关联

`POST /api/payments/intents`

```json
{ "afdianId": "<32位爱发电作者UID>", "amountCents": 2550 }
```

返回：

```json
{
  "data": {
    "intentId": "<32位随机十六进制ID>",
    "readToken": "<64位随机十六进制查询凭证>",
    "expiresAt": 1791818300000
  }
}
```

金额单位为整数分。intent 从创建起有效 5 分钟，应在即将打开爱发电时创建。此接口保存作者 UID、建议金额和查询凭证摘要，不上传餐品、祝福或项目名称。填写 UID 不验证爱发电账号所有权。

### 接收付款通知

`POST /api/payments/webhook`

所有作者使用这个地址，路径不包含作者 ID 或秘密值。真实订单通知须通过官方 RSA 公钥验签；只有 `status: 2`、有效正金额、`custom_order_id` 对应尚未过期的 intent，且实际金额等于建议金额时，才将该 intent 更新为 `notified`。支持者在爱发电修改金额后，本站不会确认原关联，应以爱发电订单为准。

验签使用原始金额字符串，例如不能将 `"5.00"` 改写成 `"5"`。有效通知返回 `{ "ec": 200 }`；订单号和签名消息摘要全局去重，重复通知不会转移到另一个 intent，也不会延长原状态的有效期。签名缺失或错误不能更新付款状态。

爱发电开发者后台的固定测试样例单独处理：严格匹配其固定订单号、付款人、方案、金额和状态，并要求没有非空 `custom_order_id`。样例带签名时仍须验签，同时接受官方文档展示的无签名固定样例。成功返回 `{ "ec": 200 }`，不写入 intent、付款状态或订单去重记录。其他通知不能通过删除签名变成测试通知。

### 查询付款通知

`POST /api/payments/status`

```json
{ "intentId": "<赞助关联ID>", "readToken": "<私密查询凭证>" }
```

| `data.status` | 含义 |
| --- | --- |
| `pending` | 有效期内，尚未收到匹配通知；带 `expiresAt` |
| `notified` | 已收到通过检查的通知；带 `amountCents`、`receivedAt`、`expiresAt`，可选 `afdianOrderNo` |
| `unknown` | 不存在、已过期或查询凭证不匹配；不代表未付款 |

时间均为 Unix 毫秒。`afdianOrderNo` 是爱发电订单号，保留前导零，为 1–64 位数字字符串；小票据此生成 Code 128 条码。缺少订单号时显示占位，不使用本站 intent ID 代替。小票的 `createdAt` 表示发起时间。

感谢页打开时查询一次；仍为 `pending` 且页面可见时，每隔至少 10 秒查询。收到通知、无法确认、网络出错、隐藏或离开页面后停止；切回页面会检查待确认记录，并恢复有效等待窗口内的查询。网络错误可手动重试，不能据此判断付款失败。

## 数据与有效期

- 等待通知的 intent 有效 5 分钟；收到匹配通知后，从首次通知起再保留 5 分钟，重试不续期。查询严格检查过期时间，Cron 每 5 分钟批量清理过期 intent。
- D1 保存 intent 的作者 UID、建议金额、查询凭证摘要及时间。匹配后保存的明文爱发电订单号随 intent 删除。
- 平台订单号和原始签名消息的 SHA-256 摘要、首次接收时间及匹配的 intent ID 长期保留，用于全局去重；签名消息摘要也防止无分隔符签名字段被重新拆分后重放。这些记录不保存明文订单号、金额或付款人标识。
- 支持者的浏览器最多保存 5 份小票，创建 30 分钟后不再恢复。内容包括赞助配置、餐单、金额、祝福、intent ID、私密 `readToken` 和可选订单号；不保存付款状态，每次恢复都重新查询服务器。浏览器的 30 分钟保留期不会延长 D1 状态有效期。
- 作者端不保存接入凭证。清除站点数据或换浏览器只会失去本地小票查询凭证，无需重新注册作者；更换域名时需更新爱发电后台地址和分享链接。
- 不保存原始 Webhook 请求、付款人 UID、餐品、留言、联系方式或地址到服务端。生产 Worker 日志保持关闭。

通知状态与去重记录通过 D1 事务写入，查询使用主库。浏览器无法保存小票时会提示，不会将无法恢复的记录当作已跟踪付款。

## 通知的可信范围

爱发电 RSA 签名覆盖 `out_trade_no + user_id + plan_id + total_amount`，没有覆盖 `custom_order_id`、`status` 或收款作者身份；其中 `user_id` 是付款人，不是作者。统一 Webhook 按未签名的关联字段匹配 intent，验签、金额检查和全局去重不能独立证明关联字段或收款关系。

因此本站使用 `notified` 和“已收到付款通知”，用于感谢小票，不据此发货、发权益或提供独立支付凭证。实际订单以爱发电为准；若以后需要严格核验，应另行接入经作者授权的查单能力，本版不收集该 API Token。

## 本地开发与部署

```sh
npm ci
npm run build
npx wrangler d1 migrations apply PAYMENTS_DB --local
npx wrangler dev --ip 127.0.0.1 --port 4173
```

本地 D1 数据位于被 Git 忽略的 `.wrangler/`，不访问生产数据库。Wrangler 使用构建后的 `dist/public/`，前端修改后需重新构建。`npm start` 和 `npm run dev` 的 Node 服务没有 D1 binding，付款接口返回 503；完整后端使用 Wrangler。预览模式不调用真实付款或 MCP 接口。

GitHub Actions 部署前自动查找或创建 D1 数据库并应用迁移。Cloudflare token 需要账户的 D1 编辑权限；缺少权限时部署失败，不会改用内存状态或自动购买付费计划。

`0002_payment_order_number.sql` 增加订单号字段；`0003_universal_webhook.sql` 将已经执行早期迁移的开发数据库转换为统一 Webhook 所需结构，保留 intent 和去重数据并移除作者接入表。应在部署新 Worker 前应用全部迁移；当前接口不提供运行时兼容路径。

Cloudflare Cron 要求账户已注册 `workers.dev` 子域名。部署脚本保留已有设置，仅在官方接口明确返回尚未注册时创建 `buy-me-a-big-mac-<账户ID前8位>.workers.dev`；网站仍使用自定义域名，`workers_dev` 和预览地址保持关闭。
